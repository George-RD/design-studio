# Triage

Move issues through category roles (`bug`, `enhancement`) and one state role: `needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, or `wontfix`.

Every issue-tracker comment posted during triage must start with:

> *This was generated by AI during triage.*

Read `AGENT-BRIEF.md` for durable agent briefs and `OUT-OF-SCOPE.md` for persistent records of rejected enhancements.

Before recommending a state, read the full issue, comments and labels; inspect relevant code using project vocabulary and ADRs; search for an existing implementation; and check prior out-of-scope decisions. Verify bug claims or PR behavior before making an agent brief. A `ready-for-agent` outcome requires concrete desired behavior, key interfaces, acceptance criteria and explicit scope boundaries.
