# Overhaul mode

## Purpose

Define how Studio redesigns an existing surface without confusing confirmed product truth and behaviour with replaceable incumbent styling.

## Triggers

Load when the user asks to redesign, rebuild, rebrand, change direction, materially raise originality, or evidence shows the settled visual world must be reopened. Use Review instead when the user wants audit/polish while preserving the current world.

## Required context

Separate: (1) product truth, (2) behaviour/data/tasks/accessibility obligations, (3) explicit commitments the user said to retain, and (4) incumbent visual styling. Capture baseline desktop/mobile render evidence when possible; Planner/Orchestrator/Builder may inspect source, Visual Director may receive baseline screenshots but not source.

## Outputs and handoff

Record the preservation contract in run planning/surface evidence and store baseline evidence under the run baseline path defined by `workflow.yaml`. Direction work treats incumbent styling as evidence and anti-reference, while preserving the first three categories unless the user changes them.

## Authority boundary

This leaf owns overhaul scope and preservation. `workflow.yaml` owns paths/budgets/transitions, `references/rationale.md` owns source-blind divergence, and Builder owns implementation fidelity. It does not authorize copy invention or product changes.

## Failure behavior

If baseline capture fails, record the exact limitation; direction may proceed from product truth, but final visual selection still requires later browser evidence. URL-only targets start fresh unless source arrives. A PIVOT starts from clean product behaviour/content rather than carrying abandoned visual code.

## Evaluation hooks

Verify that three directions are materially different, retained commitments remain intact, mobile is recomposed rather than merely stacked, and no candidate is a cosmetic reskin of the baseline. Final evidence must beat or intentionally replace the incumbent world without regressing confirmed functionality.
